# Warnings

kelex reports anything it reads from your schema but cannot represent. It never drops it in silence. Each warning on the descriptor has three parts:

- `code`: a stable string. Switch on this.
- `path`: where it happened, as Standard Schema path segments (object keys and array indices). An empty path means the whole form.
- `message`: prose for a person. Its wording can change; do not parse it.

```typescript
const { warnings } = introspect(schema, { formName: "Signup" });
for (const w of warnings) {
  if (w.code === "refine-unrepresented") reapplyOnServer(w.path);
}
```

Most warnings mean the same thing for you: the rule still holds in your schema, so validate with the schema on the server (the POST handler does), and do not expect the generated form to enforce it in the browser.

## The codes

| code                       | when kelex emits it                                                                                                                                                                                                                                                                                                                                                                                       | what to do                                                                                                               |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| `unsupported-type`         | A field's type has no form equivalent: `bigint`, `symbol`, `map`, `set`, `file`, `promise`, `function`, `custom`, and similar. The field is carried as a plain string. Also emitted for a `z.lazy` whose getter cannot be read.                                                                                                                                                                           | Expect a text input. Validate the real type on the server. Any checks on the field get their own warnings, listed below. |
| `refine-unrepresented`     | A custom check: `.refine()`, `.superRefine()`, `.check()`, or the predicate of `z.custom()`. A check on the root schema, or on a member of an intersection, is reported with its message when that is a literal string, at the path the check names (the empty path when it names none). Any other check is reported at the field it sits on, without its message.                                        | Keep the check in the schema you validate with on the server. kelex records that a check exists, not what it tests.      |
| `catch-fallback-dropped`   | A field has `.catch()`. Zod stores the fallback as a function, so kelex cannot record its value.                                                                                                                                                                                                                                                                                                          | Apply the fallback where you parse submitted data.                                                                       |
| `default-unstable`         | A `.default()` returns a different value on each call, such as `() => Math.random()` or `() => crypto.randomUUID()`. No default is recorded. kelex compares two reads, so a default that changes slowly, like `() => Date.now()`, can read the same twice and be recorded as a fixed value.                                                                                                               | Set the initial value yourself if the form needs one.                                                                    |
| `transform-output-dropped` | A field has `.transform()` or `.pipe()`. kelex reads the input side, which is what the form collects, but not the output side.                                                                                                                                                                                                                                                                            | Run the schema on the server to get the transformed value.                                                               |
| `coerce-unrepresented`     | A field uses `z.coerce.*`. The form collects the raw input; the coercion happens only when the schema parses it.                                                                                                                                                                                                                                                                                          | Parse submissions with the schema, not with a hand-written check.                                                        |
| `key-policy-unrepresented` | An object is strict, has a `catchall`, or passes unknown keys through. The descriptor does not carry the policy.                                                                                                                                                                                                                                                                                          | Enforce unknown-key rules with the schema on the server.                                                                 |
| `format-unrecognized`      | A string format kelex has no mapping for, such as `z.ipv4()` or `z.jwt()`. The field is a plain string input.                                                                                                                                                                                                                                                                                             | Validate the format on the server.                                                                                       |
| `check-dropped`            | A check kelex cannot carry: any check on a field that fell back to a string, or an unknown check on a supported type. On a fallback field the message names the check the way you wrote it, for example `>= 5n`, `max size 10`, or the implied range of `z.uint64()`. On a supported type it names Zod's internal check kind, which can differ from the method you called: `.trim()` reports `overwrite`. | The bound is not enforced by the form. Validate it on the server.                                                        |
| `record-key-narrowed`      | A `z.record` has a key schema other than a plain string. Only the value schema is carried.                                                                                                                                                                                                                                                                                                                | Validate keys on the server.                                                                                             |
| `intersection-key-overlap` | Both members of an intersection declare the same key. The right-hand definition wins.                                                                                                                                                                                                                                                                                                                     | Declare the key once, or accept the right-hand definition.                                                               |
| `numeric-enum-as-union`    | An enum has number values. They are carried, but the schema-writer re-emits them as a union of literals.                                                                                                                                                                                                                                                                                                  | Only matters if you regenerate Zod from the descriptor.                                                                  |
| `discriminator-unresolved` | A variant of a discriminated union has a discriminator that is not a literal. Its value is not recorded.                                                                                                                                                                                                                                                                                                  | Use a literal discriminator in each variant.                                                                             |
| `discriminator-ambiguous`  | A plain `z.union` has more than one field that could discriminate its variants, so kelex promoted none.                                                                                                                                                                                                                                                                                                   | Use `z.discriminatedUnion`, or remove the ambiguity.                                                                     |
| `target-warning`           | A `kelex generate` target reported a problem. Only the codegen path emits this.                                                                                                                                                                                                                                                                                                                           | Read the message; it comes from the target.                                                                              |
| `target-field-unprocessed` | A `kelex generate` target did not report handling a field, so its output may be missing it. Only the codegen path emits this.                                                                                                                                                                                                                                                                             | Check the target's output for that field.                                                                                |
